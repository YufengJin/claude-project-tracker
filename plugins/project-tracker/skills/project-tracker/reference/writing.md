# 怎么写：字段规则与正反例

模板在 [templates/](templates/)，`pt.sh new` 会自动实例化。字段名固定，不改名、不省略，空的写 `无`。日期一律 `YYYY-MM-DD`。

## 判据

一条内容值不值得写：**一个月后、在另一个话题的会话里，这条还有用吗？**
目标、决策、约束、死路、用户原话：有用。"改了 3 个 typo"、"重构了一下"：没用，看 commit。

用户说的和你推断的分开。推测要标"（推测）"。用户答不上的写"待定"，**不要替用户猜然后写成事实**，后续会话会把它当用户原话执行。

## journal 条目

```
## YYYY-MM-DD · session N · @hostname
Goal:     这次打算做什么
Did:      实际做了什么
Result:   成功 / 失败 / 部分。必须带证据
Learned:  之前不知道、现在知道的。失败的路写这里，并同步到 state 的"别再试"
Commits:  相关 commit 短哈希或分支，无则写 无
Next:     下一步，具体到能直接动手
Open:     新冒出来的问题
```

- `Result` 反例："完成了"。正例："完成。`pytest tests/ -q` 从 12 failed 降到 0 failed，41s"。
- `Learned` 反例："学到很多"。正例："Tsit5 对这个 ODE 太刚性会发散，换 Kvaerno5 后收敛"。
- session N = `grep -c '^## ' journal.md` + 1，brief 会直接打印（连同本机 hostname）。标题里的 `@hostname` 让多机时知道这条是在哪台机器上写的。**一段上下文只有一条**：同一段上下文里再次 checkpoint 只改写本段这条末尾条目，历史条目一个字节都不动；上下文压缩之后另起一条（压缩后的简报会给新号），不回头续写压缩前那条。
- 条目写增量，不重述前面条目已有的内容。长证据（日志、表格、逐项结果）放产物文件，条目里记路径和关键数字——brief 只打印最后 3 条里靠后的约 6000 字，超出的部分下个会话默认看不到。

## state.md

- 「一句话概括」的第一行就是 INDEX 里的一句话，`pt index` 会改写它；后面几行随意补充。
- 硬上限 100 行、约 8000 字（一行别写成一段）。超了就把"已完成"整段挪进 `archive/state-YYYY-MM-DD.md`（顶部加一行 `Archived from state.md on YYYY-MM-DD`），这里留一行摘要。
- "别再试"是最值钱的一节：走不通的路 + 为什么。每次 checkpoint 从 journal 的 `Learned` 提升过来。有研究树的项目例外：走不通的路写节点 `## 结论`、「别再这样做」写根 `## 教训`、现在相信什么写根 `## 当前认识`，state 不写「当前认识」「别再试」（brief 看到会提示）。
- "快速启动"要能直接复制运行。

## plan.md

写"打算怎么做"，与 state 的"现在在哪"分开。已完成步骤保留打勾。重大方向调整先在 journal 记一条为什么，再重写。

## decisions.md

只追加，编号递增。推翻旧决定：新增一条 ADR，把旧条目 `Status` 改为 `已推翻（见 ADR-00NN）`，这是对已有条目唯一允许的修改。

## charter.md

- `Workdir`：一个或多个绝对路径，空格分隔。SessionStart hook 只在当前目录落在其中之一时才加载这个项目。项目跨仓库就写多个。
- `Host`：代码和硬件所在机器的 hostname，`Workdir` 按那台机器解释。立项时自动填本机；代码在别处用 `pt new --host`。`待定位` 表示迁移时判断不出来，要手工改。
- `Status`：`进行中` `暂停` `已完成` `已放弃`，后面可以加括号注（`进行中（探索期）`），脚本只看注前面的状态值。用 `pt.sh index <slug> "<一句话>" <状态>` 改，会同步 INDEX；第二个参数是 INDEX 的一句话，不是提交说明，不能有换行。
- 完成标准打勾的唯一依据是 journal 里有对应证据条目。

## verifier.md、experiments.md 与 tree/（研究项目）

- `verifier.md`（考官卡）：拿什么判对错、真值哪来、指标与聚合怎么定义、判定依据；不知道写「未知」。状态行写 `Status: 已冻结（…）`（状态值以「冻结」或「已冻结」开头；「未冻结」「待冻结」不算）之后，`pt brief` 只打印状态行与「指标与聚合定义」「判定依据」两节。
- `experiments.md`（台账）：一行一个实验，`id | node | 问题 / 对照 | 读数 | 运行 | 结论 | 证据`。`node` 填研究树节点 ID，多个用逗号分隔，没有就空着；单元格里的竖线写 `\|`。可以分多个 `## ` 小节、多张表；表头有 `node`（或「节点」）列的表才会挂到节点上；注释与代码块里的表格行不算。行不删：确认阶段可以先占一行（读数空着）、跑完回填，更正留痕。
- 确认阶段「占行后先提交」：`git -C <档案> add tree/<ID>.md experiments.md && git commit -m "占行 <实验 id>"`。不用 `pt index`，它会改 state 的一句话和 INDEX。
- `tree/<ID>.md`（研究树节点），例：

```
---
title: 遮挡下误差主要来自匹配层，而不是求解器
parent: Q2
status: closed
verdict: refuted
---
## 判别
预测：换成真值匹配后误差降一半以上。降不到 20% 就说明错了。对立解释：求解器的初值。预算：半天。

## 结论
不支持：真值匹配只降了 8%（E14，证据 results/e14/summary.md）。转去看初值，见 [[H9]]。
```

  - `status` 是工作安排（`open` 没开始、`active` 在做、`parked` 先放下、`closed` 结束）；`verdict` 是证据判断，只在 `closed` 时写。被新假设取代写 `verdict: superseded` 加 `by: H9`。没有判别证据就停（用户或预算决定）写 `verdict: abandoned`，结论写谁定的、为什么。
  - 假设节点的 verdict：`supported` / `refuted` / `inconclusive` / `superseded` / `abandoned`。问题节点答完时：`supported`（答案成立）/ `inconclusive` / `abandoned` / `superseded`；`refuted` 只用于假设。
  - `## 判别` 跑之前写：预测、什么结果说明它错、对立解释、预算；问题节点只写为什么问、什么算答完，不写候选与排名（`--blind` 要拿它给没见过猜想的 agent）。事后补的标「事后整理」，不知道的空着。
  - `## 结论` 关的时候写：判断、怎么知道的、引用实验 id 与证据路径，不抄读数。之后发现写错了，就地改：把首句改成新判断（`--all` 索引取首句），末尾注明更正原因与日期；命题实质变了才新建节点。同一节只写一个 `## 结论`，写了两个脚本告警并取最后一个。
  - `parked` 的节点：搁置理由和已有的部分读数写进 `## 结论`，首行写「未关：」，只引用实验 id，不抄读数。
  - 每个根有自己的 `## 当前认识`（属于这个根的目标：现在相信什么、依据哪几行实验；不在 state 复写）、`## 约束`（协议、切分与暴露、禁读的东西，每份 `--ctx` 都带；引用别的根写 `[[Q5]]`，那个根的约束会一并带上）、`## 教训`（人工提炼，每条写适用条件与出处）。脚本只做索引和检查，不替你下结论。
  - `<!-- -->` 注释不进简报和 tree.html，模板里的说明就写在注释里；注释里的标题和表格行不算数，没闭合的 `<!--` 一直吃到文末（会告警）。

## INDEX.md

```
| Slug | 名称 | 状态 | 主机 | 最后更新 | 一句话 |
```

生成视图，不手编：名称取 charter 标题，状态取 `Status`，主机取 `Host`（本机显示"本机"），日期取最后一次提交（迁移提交不算；只有迁移提交时取 journal 最后一条的日期），一句话取 state「一句话概括」首行。`pt new` / `pt index` / `pt list` / 同步都会重建它。
