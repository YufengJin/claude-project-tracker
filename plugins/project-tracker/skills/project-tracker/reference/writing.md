# 怎么写：字段规则与正反例

模板在 [templates/](templates/)，`pt.sh new` 会自动实例化。字段名固定，不改名、不省略，空的写 `无`。日期一律 `YYYY-MM-DD`。

## 判据

一条内容值不值得写：**一个月后、在另一个话题的会话里，这条还有用吗？**
目标、决策、约束、死路、用户原话：有用。"改了 3 个 typo"、"重构了一下"：没用，看 commit。

用户说的和你推断的分开。推测要标"（推测）"。用户答不上的写"待定"，**不要替用户猜然后写成事实**，后续会话会把它当用户原话执行。

## journal 条目

```
## [YYYY-MM-DD] 类别 | 节点或线程 | 一句话
Goal:     这次打算做什么
Did:      实际做了什么
Result:   成功 / 失败 / 部分。必须带证据
Learned:  之前不知道、现在知道的。失败的路写这里，并同步到节点结论或 state 的"别再试"
Next:     下一步，具体到能直接动手
Open:     新冒出来的问题
```

类别取 `结果` `决定` `方向` `运维` `评审` 之一（简报跳过「运维」）；标题的方括号、空格与两个 ` | ` 照写，脚本靠它认日期和类别。0.7.0 之前的 `## YYYY-MM-DD · session N · @host` 旧条目不改写。

- `Result` 反例："完成了"。正例："完成。`pytest tests/ -q` 从 12 failed 降到 0 failed，41s"。
- `Learned` 反例："学到很多"。正例："Tsit5 对这个 ODE 太刚性会发散，换 Kvaerno5 后收敛"。
- **一段上下文只有一条**：同一段上下文里再次 checkpoint 只改写本段这条末尾条目，历史条目一个字节都不动；上下文压缩之后另起一条，不回头续写压缩前那条。
- 条目写增量，单条不超过 3 KB，不重述前面条目已有的内容。长证据（日志、表格、逐项结果）放产物文件，条目里记路径和关键数字——简报只给最近 8 条的标题，正文下个会话默认看不到。

## state.md

- 小节固定（见 SKILL.md「快照写什么」），名字照写；`## 待拍板（2 项）` 这样带括号注也认。不合格就走旧版简报，`pt lint` 会说缺哪节、多了哪节。
- 「一句话概括」的第一行由 `pt index` 改写（`pt list --tsv` 的 summary 列、research.html 卡片用它），`Updated:` 行也由它写。
- 没有研究树的项目可以加 `## 当前认识`（可选，放最后）：现在相信什么，不超过 15 条，重写不追加；第 1 条进 `pt list`。
- 「焦点」里写的 `Q12` / `H34` 这类 ID 就是焦点链的终点：简报和 `pt tree` 据此取根到它这条链上的当前认识。
- 全文不超过 3 KB：每次重写，不追加。做完的事进 journal，旧内容挪进 `archive/state-YYYY-MM-DD.md`。
- 「快速启动」要能直接复制运行。

## plan.md

只有工程项目写，研究项目不要（前沿就是计划）。一步一行 `- [ ] 步骤 → 验证：命令或判据`，做完改成 `- [x MM-DD] 步骤 → 证据路径`。还是模板的 plan 不进简报，`pt lint` 会报。方向调整先写 ADR，再重写。

## decisions.md

只追加，编号递增。推翻旧决定：新增一条 ADR，把旧条目 `Status` 改为 `已推翻（见 ADR-00NN）`，这是对已有条目唯一允许的修改。

## charter.md

- `Workdir`：一个或多个绝对路径，空格分隔。SessionStart hook 只在当前目录落在其中之一时才加载这个项目。项目跨仓库就写多个。
- `Host`：代码和硬件所在机器的 hostname，`Workdir` 按那台机器解释。立项时自动填本机；代码在别处用 `pt new --host`。`待定位` 表示迁移时判断不出来，要手工改。
- `Status`：只取 `进行中` `暂停` `已完成` `已放弃`，备注写到 state（带括号注的 `pt lint` 会报；脚本仍按注前面的状态值算）。用 `pt.sh index <slug> "<一句话>" <状态>` 改，会同步 INDEX；第二个参数是 state 的一句话，不是提交说明，不能有换行。
- 完成标准只是目标陈述，不打勾、不当进度；进度看 plan 勾选（`pt list`）。

## verifier.md、experiments.md 与 tree/（研究项目）

- `verifier.md`（考官卡）：拿什么判对错、真值哪来、指标与聚合怎么定义、判定依据；不知道写「未知」。状态行写 `Status: 已冻结（…）`（状态值以「冻结」或「已冻结」开头；「未冻结」「待冻结」不算）之后，`pt brief` 只打印状态行与「指标与聚合定义」「判定依据」两节。
- 档案根的 `.ignore`（`tree.html`）与 `.gitattributes`（`tree.html -diff`）由 pt 补上，让搜索跳过、git diff 不展开这个生成的大文件；不用手改。
- `experiments.md`（台账）：一行一个实验，`id | node | 问题 / 对照 | 读数 | 运行 | 结论 | 证据`。`node` 填研究树节点 ID，多个用逗号分隔，没有就空着；单元格里的竖线写 `\|`。可以分多个 `## ` 小节、多张表；表头有 `node`（或「节点」）列的表才会挂到节点上；注释与代码块里的表格行不算。行不删：确认阶段可以先占一行（读数空着）、跑完回填，更正留痕。
- 确认阶段「占行后先提交」：`git -C <档案> add tree/<ID>.md experiments.md && git commit -m "占行 <实验 id>"`。不用 `pt index`，它会改 state 的一句话。
- `tree/<ID>.md`（研究树节点），例：

```
---
title: 遮挡下误差主要来自匹配层，而不是求解器
parent: Q2
status: closed
verdict: refuted
---
## 判别
预测：换成真值匹配后误差降一半以上。降不到 20% 就说明错了。对立解释：求解器的初值。预算：半天。

## 结论
不支持：真值匹配只降了 8%（E14，证据 results/e14/summary.md）。转去看初值，见 [[H9]]。
```

  - `status` 是工作安排（`open` 没开始、`active` 在做、`parked` 先放下、`closed` 结束）；`verdict` 是证据判断，只在 `closed` 时写。被新假设取代写 `verdict: superseded` 加 `by: H9`。没有判别证据就停（用户或预算决定）写 `verdict: abandoned`，结论写谁定的、为什么。
  - 假设节点的 verdict：`supported` / `refuted` / `inconclusive` / `superseded` / `abandoned`。问题节点答完时：`supported`（答案成立）/ `inconclusive` / `abandoned` / `superseded`；`refuted` 只用于假设。
  - `## 判别` 跑之前写：预测、什么结果说明它错、对立解释、预算；问题节点只写为什么问、什么算答完，不写候选与排名（`--blind` 要拿它给没见过猜想的 agent）。事后补的标「事后整理」，不知道的空着。
  - `## 结论` 关的时候写：判断、怎么知道的、引用实验 id 与证据路径，不抄读数。之后发现写错了，就地改：把首句改成新判断（`--all` 索引取首句），末尾注明更正原因与日期；命题实质变了才新建节点。同一节只写一个 `## 结论`，写了两个脚本告警并取最后一个。
  - `parked` 的节点：搁置理由和已有的部分读数写进 `## 结论`，首行写「未关：」，只引用实验 id，不抄读数。
  - 任何问题节点可以有 `## 当前认识`（这个问题下现在相信什么、依据哪几行实验）：每次重写，不超过 15 条或 3 KB，不写「当前认识更新」「历史认识」这类追加小节，旧版交给 git 与 journal。根节点的只放跨分支的认识；每个根另有 `## 约束`（协议、切分与暴露、禁读的东西，每份 `--ctx` 都带；引用别的根写 `[[Q5]]`，那个根的约束会一并带上）、`## 教训`（人工提炼，每条写适用条件与出处）。脚本只做索引和检查，不替你下结论。
  - `<!-- -->` 注释不进简报和 tree.html，模板里的说明就写在注释里；注释里的标题和表格行不算数，没闭合的 `<!--` 一直吃到文末（会告警）。

## INDEX.md

```
| 项目 | 状态 | 最近活动 | 距今 | 等用户 | 进度 | 在跑 | 现在最信的一条 |
```

算出来的进度总览，不手编（`scripts/progress.py`；`pt list`、research.html 顶部、简报的 INDEX 行同一份数据，按各项目 HEAD 与文件 mtime 缓存在 `<档案根>/.cache/`）。各列口径见 SKILL.md 的 `pt list`；要让它算得出，只靠这几处手写约定：待拍板每条以 `[待用户 MM-DD]` 开头、journal 新格式标题（运维条目不算活动）、plan 勾选、「当前认识」第 1 条。`pt new` / `pt index` / `pt list` / 同步都会重建它。
